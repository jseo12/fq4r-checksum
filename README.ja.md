# FQ4R セーブデータチェックサムCLIツール

[English](README.md) | [한국어](README.ko.md) | **日本語**

ファーストクイーンⅣ Windows版のセーブデータのチェックサムを検証・修正するツールです。本プロジェクトでは、このWindows版を **FQ4R** と表記します。公式の日本語製品名は「ファーストクイーンⅣ」です。[公式サイト](http://kure.sakura.ne.jp/fq4/)

リポジトリ名は `fq4r-checksum`、実行ファイル名は `fq4r-checksum.exe` です。Windows x86・x64向けのCプログラムで、Windows標準DLLと静的リンクしたCランタイムを使用します。ブラウザーエンジン、Node.js、Python、別途VCランタイムのインストールは実行に不要です。Pythonはテスト時のみ使用します。

## 使い方

ダウンロードしたEXEのあるフォルダーで実行してください。ソースからビルドした場合は `bin` に生成されます。

```powershell
# ファイル指定：ファイル名の制限なし
.\fq4r-checksum.exe "C:\Games\FQ4R\custom.dat"

# フォルダー指定：save00.dat～save99.datを検査
.\fq4r-checksum.exe "C:\Games\FQ4R"

# バックアップ後、不正なチェックサムを修正
.\fq4r-checksum.exe --fix "C:\Games\FQ4R"

# 言語選択とヘルプ
.\fq4r-checksum.exe --lang ja "C:\Games\FQ4R\save00.dat"
.\fq4r-checksum.exe --help
```

| 引数・オプション | 動作 |
|---|---|
| ファイルまたはフォルダー | パスを1つ指定（必須） |
| `-f`, `--fix` | チェックサムが不正なファイルのみバックアップして修正 |
| `-l`, `--lang ko\|en\|ja\|auto` | 表示言語を選択。`--lang=ja` も使用可能 |
| `-h`, `--help` | 使い方と言語選択の案内を表示 |
| `--` | 以降の引数をオプションとして解釈しない |

フォルダー内では、数字が正確に2桁の `saveNN.dat` を大文字小文字の区別なく、ファイル名順に検査します。サブフォルダーは検索しません。ファイルを直接指定した場合は名前を制限しません。

すべてのファイルで、サイズが **32768バイト**、signatureが **`win4` または `Win4`** であることを確認します。`WIN4` は受け付けません。形式・入出力エラーを表示して次のファイルへ進み、不正な形式のファイルは修正しません。8領域それぞれの範囲、保存値、計算値、一致状況を表示します。

## 言語と終了コード

既定の `auto` はWindowsユーザーの表示言語から韓国語・英語・日本語を選択します。未対応の言語は韓国語になります。地域の書式設定やコンソールのコードページとは別です。明示的な言語指定を優先し、複数指定した場合は最後の値が適用されます。言語コードは大文字小文字を区別せず、設定は保存しません。

引数がない場合は、エラーと言語選択案内を含むヘルプを表示します。`--help --lang ja` のようにヘルプの後に言語を指定しても適用されます。出力はUTF-8です。指定言語のWindowsエラーメッセージリソースがない場合は、翻訳済みの一般的な説明とWindowsエラー番号を表示します。

| 終了コード | 意味 |
|---|---|
| `0` | すべて正常または修正完了、もしくはヘルプ表示 |
| `1` | チェックサム不一致が残っている |
| `2` | 形式・入出力・引数エラー、または対象なし |

`2` は `1` より優先されます。集計には、検査数、元から正常な数、修正完了数、検査モードでの不一致数、形式エラー数、その他のエラー数を表示します。検索エラーはファイル数とは別に加算される場合があります。

## 修正とバックアップ

元のファイル全体を `.bak` にコピーします。既存の場合は `.bak.1`、`.bak.2` の順で以前のバックアップを保持します。バックアップが検査時点の入力と同じ内容かも確認します。バックアップに失敗した場合は修正しません。正常なファイルは変更・バックアップしません。

同じフォルダーの一意の一時ファイルに修正結果を書き込み、flush後に `ReplaceFileW` で置き換えます。変更するのは **`0x7DA6～0x7DAD` の8バイトのみ**です。失敗時も作成済みのバックアップは保持します。他のプログラムによる同時保存・置き換えを完全に調整するものではないため、ゲームを終了してから修正してください。

正常なチェックサムは、ゲームデータの意味的な正しさやロード成功を保証しません。開発時に韓国語パッチ版のセーブ8件を検査しましたが、すべての言語版・更新版・Windowsバージョンでの動作を検証したわけではありません。

## ビルドとテスト

Visual StudioのC++デスクトップビルドツールとWindows SDKが必要です。

```powershell
.\build.cmd
.\bin\fq4r-checksum.exe --help
python .\test_cli.py
```

現在のVisual Studioまたは `vswhere` で検索したインストール先を使用して、指定した対象環境を初期化します。サイズ最適化、CRTの静的リンク、警告のエラー化を有効にします。MSVCを手動設定する場合はx64 Native Toolsプロンプトを使用してください。

テストは合成セーブデータと独立したPython XOR実装を使用するため、ゲームファイルなしで実行できます。全領域とチェックサム保存領域の改変、バックアップ保持、繰り返し修正、不正な形式、名前フィルター、Unicode・長いパス、読み取り専用ファイル、3言語を検証します。修正テストは一時コピーのみを変更します。元の分析用ワークスペースに実セーブがある場合の追加検査は、ファイルがなければスキップします。

## アーキテクチャ別のビルド

```powershell
.\build.cmd x64
.\build.cmd x86

# x86実行ファイルで統合テスト
$env:FQ4R_CHECK_EXE = "$PWD\bin\x86\fq4r-checksum.exe"
python .\test_cli.py
Remove-Item Env:FQ4R_CHECK_EXE
```

- x64：`bin/fq4r-checksum.exe`。引数なしの場合も既定です。
- x86：`bin/x86/fq4r-checksum.exe`。32ビットWindowsユーザー向けです。

対象アーキテクチャを明示的に選択し、成果物を分離します。共通のCソースとリリース設定を使用します。x86実行ファイルは現在の64ビットWindows環境で検証しており、実際の32ビットWindows環境では未検証です。古いWindowsバージョンとの互換性を保証するものではありません。

## リリースパッケージ

ビルド成功時に `dist/` へ配布用ZIPを自動生成します。

```powershell
.\build.cmd       # x64のビルドとZIP生成
.\build.cmd x86   # x86のビルドとZIP生成
.\build.cmd all   # 両アーキテクチャのビルドとZIP生成
```

バージョンは `VERSION` から読み取ります（現在 `0.1.0`）。出力名は `fq4r-checksum-v0.1.0-windows-x64.zip` と `fq4r-checksum-v0.1.0-windows-x86.zip` です。各ZIPの最上位には `fq4r-checksum.exe`、`LICENSE`、`README.md`、`README.ko.md`、`README.ja.md` の5ファイルのみを含めます。サンプルと中間成果物は除外します。再ビルド時は、新しいZIPの完成後に同じバージョン・アーキテクチャのパッケージを置き換えます。

`package.ps1` はWindows PowerShellと.NETを使用し、追加の圧縮ソフトは不要です。PEアーキテクチャと必須ファイルを確認し、パッケージ作成の失敗もビルドコマンドの失敗として扱います。既存のEXEを再パッケージするには `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\package.ps1 -Architecture x64` を実行します（`x86` も指定可能）。ZIPはGitの対象外で、GitHub Releaseの添付ファイルとしてアップロードできます。タグ作成・コミット・プッシュ・リリース公開は自動実行しません。

## GitHub Actionsによるビルド

`.github/workflows/build.yml` はWindowsランナーでx86・x64を個別にビルド・テストし、配布ZIPをワークフローのアーティファクトとしてアップロードします。`main` へのプッシュ、`v*` タグのプッシュ、`main` 向けプルリクエスト、手動実行に対応します。バージョンタグは `VERSION` と一致する必要があります。

ワークフローをコミット・プッシュした後、**Actions → Build Windows binaries → Run workflow** から手動実行できます。完了した実行の **Artifacts** からダウンロードしてください。`upload-artifact@v7` の `archive: false` を使用するため、追加のZIP包装なしで配布ZIP自体がアーティファクトになります。各アーキテクチャのアーティファクトを個別にダウンロードし、そのZIPをGitHub Releaseへ直接添付できます。保存期間はリポジトリのポリシーの範囲内で14日です。

このワークフローはビルド成果物のみをアップロードし、GitHub Releaseを作成・公開しません。選択したコミットにワークフローが必要なため、最初のコミットを指す既存の `v0.1.0` タグには遡って適用されません。

## 構成とAPIドキュメント

- `fq4r_checksum.c`, `fq4r_checksum.h`：Windows APIに依存しない共通Cモジュール。関数は `fq4r_`、定数は `FQ4R_` を使用します。
- `main.c`：Windowsのファイル処理とCLI。
- `i18n.h`：韓国語・英語・日本語の出力。
- `test_cli.py`：CLI統合テスト。
- `Doxyfile`：APIドキュメント生成設定。

保存済みチェックサム8バイト全体を0として扱い、4096バイトずつ8領域のXORを計算した後、すべての結果を書き込みます。共通モジュールは将来のGUIでも直接利用できます。

Doxygenコメントは英語の次の行に韓国語を記載し、引数の方向、戻り値、事前条件、バッファーの所有権を説明しています。Doxygenのインストール後、このフォルダーで `doxygen Doxyfile` を実行すると `docs/generated/html/index.html` が生成されます。Doxygenはビルド・実行に不要です。

`.gitignore` はビルド成果物、生成ドキュメント、キャッシュ、ローカルIDE設定、セーブ、バックアップを除外します。ゲーム実行ファイルや実セーブをリポジトリへ含める必要はありません。
